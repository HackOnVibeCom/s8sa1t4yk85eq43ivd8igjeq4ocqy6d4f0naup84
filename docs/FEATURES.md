# Features and implementation status

This status describes repository evidence; it is not a production acceptance test. "Implemented" means a code path exists, not that every integration has been verified against a live deployment.

| Area | Current status | Important qualification |
|---|---|---|
| Landing and venue discovery | Implemented prototype | Includes sample venues and navigation. Search/location coverage is limited; this is not a comprehensive place directory. |
| Venue details | Implemented prototype | Attributes and photos are driven by available application data; evidence freshness and completeness are not guaranteed. |
| Map | Implemented prototype | React Leaflet with OpenStreetMap tiles and a fixed/sample Chennai-area dataset. It is not a live geocoder or routing service. |
| Accessibility filters | Partial | UI controls exist; verify each control against the current data and result set before demonstrating it. |
| Citizen authentication | Implemented with Supabase | Requires a configured project. There are no built-in demo credentials or client-side admin passwords. |
| Community contribution form | Partial | Multi-step UI exists, but not every form field and uploaded file is fully represented in cloud persistence. |
| Photo evidence gallery | Prototype/local interactions | Sample gallery, comments, helpful count and confirmation behavior are not all persisted as shared community records. |
| Reports and disputes | Partial | Report flow exists, but portions use fixed sample venue/contribution references and do not constitute a complete moderation case-management system. |
| Admin/moderation views | Partial | Database-backed status operations exist in places; some dashboard counts and display values are hardcoded. |
| Saved venues and notifications | Implemented prototype | Persistence depends on Supabase setup; some notification behavior is local or generated by client actions. |
| AI assistant | Implemented with limitations | Server endpoint calls Gemini and returns structured, allowlisted actions. It is not a general autonomous agent and does not verify venue accessibility. |
| Voice interaction | Browser-dependent prototype | Uses browser speech recognition and speech synthesis, not a live streaming voice model. Permissions, browser support and behavior require manual testing. |
| Responsive layout | Responsive styles implemented | Mobile layouts are present in code; test on actual target browsers/devices before claiming a verified experience. |

## Not included or not verified

- A verified public production deployment or judge account
- A comprehensive, live venue database or location/geocoding backend
- Independent accessibility certification
- A complete review/dispute lifecycle with audit history and notifications
- Fully persisted community photo evidence, comments and reactions
- Gemini Live streaming or guaranteed automatic microphone startup
- An AgentRouter integration

See [known limitations](./KNOWN_LIMITATIONS.md) and the [submission readiness checklist](./HACKATHON_SUBMISSION_CHECKLIST.md).
